1. What is this app?

vMix Church Service Manager is a companion tool for church media teams. It runs as a small local web server on the media computer and does three jobs:

  1. Store hymns and songs — a searchable library where each hymn keeps two parallel sets of slides: one formatted for vMix live titles and one for PowerPoint.
  2. Plan the service — build an Order of Service (a program of events with people and descriptions) and a hymn plan (which hymns will be sung, in what order).
  3. Feed the outputs — generate ready-to-present PowerPoint files and serve live JSON feeds that vMix reads as Data Sources.
Hymn Librarynumbers, titles, lyrics
Service Plantoday's hymns, ordered
OutputsPPTX files + vMix JSON feeds
Service Programorder of service + tags
PPT Templateyour .pptx design
Data Tablescustom feeds & patterns

How the pieces fit together: everything flows toward PowerPoint files and live vMix feeds.

The interface is a regular web page — no installation is needed on other devices. Any browser on the same network can open it, and vMix (even on another machine) reads the JSON feeds over HTTP.

2. Getting started

Installation
  • Install: download vmix-church-service-manager-setup-<version>.exe from the project's GitHub Releases page and run it. The wizard installs per-user (no administrator rights needed), creates a Start Menu entry, and offers two options: a desktop icon and "Start automatically when Windows starts".
  • File locations (following Windows conventions): program files in %LOCALAPPDATA%\Programs\vMix Church Service Manager; your data (database, uploaded templates, config) in %APPDATA%\vMix Church Service Manager; log files in %LOCALAPPDATA%\vMix Church Service Manager\logs. Updates never touch your data.
  • Background app: the installed app runs without a console window. Server activity is written to rotating log files in the logs folder above.
  • Uninstall: use Windows "Apps & features". The uninstaller asks whether to keep or remove your data.
Running
  • Launch: use the Start Menu shortcut (or python app.py in development). It starts a web server on port 10001 listening on all network interfaces.
  • Open the UI: browse to http://localhost:10001 on the same machine, or http://<machine-ip>:10001 from another device on the network.
  • First run: if the configured database file cannot be found, every page redirects to Settings so you can point the app at (or create) a database and templates folder before doing anything else.
  • Theme: the sun/moon button at the right of the navigation bar toggles light and dark mode. The choice is remembered per browser.
  • Notifications: success, warning, and error messages appear as small toast panels in the bottom-right corner. They dismiss themselves after a while, or click the × to close them.

3. Dashboard

The Dashboard is the "day of service" screen — a read-mostly overview of what is live right now.

Status strip
  • When a program is active: a green LIVE badge, the program's name, and a vMix Feed button that opens /api/program/current in a new tab (handy for copying the URL into vMix).
  • When nothing is active: a red OFFLINE badge with a Go to Programs shortcut.
Order of Service panel (left)
  • Shows the active program's items in order: sequence number, event title, and the person/description subtitle. Muted items are hidden here (see muting).
  • If the program has a PowerPoint template assigned, a green Download button opens the Service Program PPT settings dialog (identical to the one in the program editor — see Service Program PPT).
  • If no template is assigned, a dimmed "No template" link takes you to the Templates manager instead.
Hymns panel (right)
  • Lists today's planned hymns with their numbers. The eye icon on each row opens the Hymn Preview dialog showing both the vMix and PowerPoint slides.
  • When hymns are planned, a Download button opens the Hymns PPT settings dialog (see Hymns PPT download).
  • When empty, a shortcut leads to the Hymns view to add some.

4. Service Programs

A Service Program is an order of service: a sequence of events (Welcome, Opening Prayer, Sermon…), each with an optional person/description and an optional PPT tag. One program at a time can be active — that is the one the Dashboard and the vMix feed serve.

Programs list (/programs)
  • New Program creates a program named "New Service Program" and opens it in the editor. Housekeeping: empty drafts you never touched (default name, no items, no template, not active) are deleted automatically next time the list is loaded — so backing out of an accidental click leaves no clutter.
  • The active program is presented as a large card with a ● LIVE NOW badge, its item count and template status, an Edit Program button, a Duplicate button, and a scrollable preview of the full order of service.
  • Other programs appear in a grid below with Set Active, Edit, and Duplicate actions.
  • Duplicate clones everything — items, tags, muted flags, and the template assignment — into a new program named "Original name (Copy)".
Program editor (/programs/{id})
Event Title Person / Description PPT Tag
Welcome Pastor John {{welcome}}

Sermon Elder Smith — "Faith" {{sermon}}

The items table: drag the grip to reorder, every cell auto-saves, the eye toggles muting. The middle row is muted — hidden from vMix and the Dashboard.

  • Program name — the large input in the top bar. It saves automatically when you click away; a small "Saved ✓" indicator confirms each save.
  • Template selector — assigns one of your uploaded .pptx templates to this program (or "No Template"). Saves automatically on change.
  • Add Event — appends a blank row. Fill in the title, person/description, and optionally a tag; each field saves when changed.
  • Reorder — drag rows by the grip handle; the new order saves on drop and is reflected everywhere (Dashboard, feed, PPT).
  • Delete row — the × at the row end removes the item immediately (no confirmation).
  • Download PPT — opens the Service Program PPT dialog (details below). Requires a template.
  • More menu (⋯) — View JSON opens the program's feed for inspection; Delete Program removes the program and all its items after a confirmation prompt.
  • A PPT Pattern Reference card at the bottom of the page summarizes all placeholder patterns currently valid for your templates, including any enabled data-table patterns.
PPT tags & muting
  • A tag connects a program item to a placeholder in your PowerPoint template: if an item has tag sermon and subtitle Elder Smith — "Faith", then every occurrence of {{sermon}} in the template is replaced with that subtitle.
  • Reserved names are rejected with an error toast, both in the browser and on the server:
    • hymn_1, hymn_2, … — reserved for hymn insertion.
    • <pattern>_1, <pattern>_2, … where <pattern> is an enabled data-table pattern name.
  • Muting (the eye toggle) hides an item from the Dashboard's Order of Service and from the vMix JSON feed — but the item's tag is still replaced in generated PowerPoints. Use it for internal notes or for items that should appear only in the printed/projected program.

5. PowerPoint templates

The Templates manager (/templates_manager, linked from the Programs page) stores the .pptx files that Service Program PPTs are built from.

Uploading
  • Drag & drop a .pptx file onto the upload zone, or click Browse files. Only .pptx is accepted; anything else shows an error.
  • The Template Name is auto-suggested from the file name (underscores and dashes become spaces) and can be edited before uploading.
  • Uploaded files are stored in the Templates folder configured in Settings.
Managing
  • Saved templates appear as cards showing the display name and the stored file name.
  • Delete asks for confirmation and warns that programs using the template will lose their assignment.
Authoring a template

Design your .pptx freely in PowerPoint, then place these placeholders in text boxes where content should be injected:

PlaceholderReplaced with
{{tag}}The Person / Description of the program item whose PPT Tag is tag.
{{name_1}}, {{name_2}}, …Values from the data table whose pattern is name — one per row, in row order.
{{hymn_1}}, {{hymn_2}}, …The whole slide is exploded into a hymn title slide plus one slide per lyrics block, using the Nth hymn of the service plan.

Style the {{hymn_N}} placeholder slide (background, positioning, font) exactly the way you want the generated hymn slides to look — the generated slides are copies of it, and with Inherit fonts from template enabled they even use the placeholder's own font (see font inheritance).

6. Hymns view

The Hymns view (/hymns) is where you pick which hymns will be sung. The left panel is today's service plan; the right panel is the full library.

A plan row: drag handle · sequence · hymn number · title · preview (eye) · remove (×).

  • Add hymns from the library (right panel) — each lands at the end of the plan.
  • Reorder by dragging the grip handle; sequence numbers renumber instantly and the order saves on drop.
  • Remove with the ×; the remaining hymns renumber automatically (1, 2, 3…).
  • The plan's order defines the hymn numbering used by {{hymn_N}} template placeholders and by the vMix hymns feed.
Hymn library & search (right panel)
  • The search box matches as you type (250 ms debounce) against hymn number, title, and the lyrics text itself, case-insensitively — so a remembered lyric fragment is enough to find a song.
  • Results sort naturally: numeric hymn numbers first in numeric order (2 before 10), then non-numeric entries alphabetically.
  • The eye icon previews any hymn (vMix and PowerPoint slide sets in two tabs); Add puts it in the plan.
  • The vMix Feed button opens the live hymns feed (/api/hymns/service) in a new tab.
Hymns PPT download

7. Hymn Editor

The Hymn Editor (/editor) is where hymns are created and their lyrics split into slides. Each hymn holds two independent slide sets: vMix (Live) for lower-third titles and PowerPoint for full-screen slides — because line lengths and block sizes usually differ between the two.

  • Sidebar — searchable hymn list (same matching rules as the library search). Click a hymn to load it; New starts a blank one. The sidebar can be collapsed with the chevron button or resized by dragging its edge (180–700 px; dragging below ~80 px collapses it).
  • Number & Title — both required. A purely numeric number (e.g. 123) is treated as a hymnal number and shown as "Hymn #123" on generated title slides; a non-numeric value is treated as a worship song and only the title is shown.
  • Save All — saves the hymn and both slide sets at once. The button shows its state: Saving… → Saved! (or Error in red). After the first save of a new hymn, the form switches to edit mode and a Delete button appears (with a confirmation prompt).
Slide source format

Each tab has a plain-text source editor on the left and a live slide preview on the right. The rules:

[Verse 1] Amazing grace, how sweet the sound That saved a wretch like me I once was lost, but now am found Was blind but now I see [Chorus] Praise God, praise God
Verse 1Amazing grace, how sweet the sound
That saved a wretch like me
Verse 1 (inherited)I once was lost, but now am found
Was blind but now I see
ChorusPraise God, praise God

A blank line starts a new slide; a [Label] line names the slide and following slides inherit the label until a new one appears.

  • Blank line (an empty line between text blocks) — starts a new slide.
  • [Label] on its own line — names the slide (Verse 1, Chorus, Bridge…). Later slides inherit the most recent label (shown dimmed in the preview) until you write a new one.
  • In the preview, labels starting with "v" get a blue badge and "c" a green badge, making verse/chorus structure easy to scan.
Line-length warnings (Wrap)
  • Each editor has a Wrap number box in its header. Set it to your safe character count per line (leave empty for no checking).
  • Characters beyond the limit are highlighted red directly in the source editor, and affected preview slides get a warning badge — so overly long lines are caught before they overflow on screen.
  • The limits are stored per slide type (vMix and PPT separately) and persist across sessions and machines using the same database.

8. How PPTs are generated

Service Program PPT (template-based)

Available from the Dashboard and the program editor when a template is assigned. The generator makes three passes over a copy of your template:

  1. Tag replacement — every {{tag}} matching a program item's PPT Tag is replaced with that item's Person/Description text (muted items included).
  2. Data table patterns — every {{name_N}} from enabled patterns is replaced with the value from row N of the corresponding table.
  3. Hymn explosion — each slide containing {{hymn_N}} is duplicated into a title slide plus one slide per lyrics block of the Nth planned hymn, then the original placeholder slide is deleted.
{{hymn_1}}
Template slide
(styled by you)
Hymn #123 Amazing Grace
Title slide
Amazing grace,
how sweet the sound…
Lyrics slide 1
I once was lost,
but now am found…
Lyrics slide 2 …

Hymn explosion: the placeholder slide's design (background, images, layout) is copied to every generated slide.

  • The title slide shows "Hymn #N" (at half the title size) above the bold title for numeric hymn numbers, or just the bold title for worship songs.
  • If the plan has no hymn at position N, the slide reads "(Hymn #N not scheduled)" so the gap is visible instead of silent.
  • The download dialog's font settings apply to hymn slides only; every other slide is your template, untouched.
Font inheritance ("Inherit fonts from template")
  • With the switch off (default), hymn slides use the Font Family, Title Size, and Lyrics Size you set in the dialog.
  • With the switch on, the manual controls are disabled and the generator reads the font of the {{hymn_N}} placeholder itself — resolving through PowerPoint's full style hierarchy (text formatting → shape → slide layout → slide master), so it works even when the font is defined on the layout rather than typed formatting.
  • Lyrics use the placeholder's font and size; titles render 20% larger than the lyrics. Each {{hymn_N}} slide is resolved independently, so different hymns can use different fonts if your template does.
  • If the template genuinely defines no font anywhere in the chain, the dialog values are used as a fallback.
Standalone Hymns PPT (no template)
  • Generated from the Hymns view or Dashboard using only the service plan — no template needed.
  • Slides are 10″ × 7.5″ (4:3) or 16″ × 9″ (16:9) with a 0.5″ safe margin, filled with your chosen background color (default black) and text color (default white), text centered vertically and horizontally with word-wrap and shrink-to-fit.
  • Per hymn: a title slide ("Hymn #N" at half title size + bold title, or just the title for worship songs), then one slide per PPT lyrics block, then an empty spacer slide before the next hymn (nothing after the last).

9. Data Tables

Data Tables (/data-tables) are free-form spreadsheets you define — announcements, Bible verses, schedules, teams. Each table is served as a JSON feed for vMix and can optionally inject its values into PowerPoint templates.

Creating and editing
  • New Table asks for a name and column names (add or remove columns freely).
  • In the table editor, cells are auto-expanding text areas that save on change; rows drag-reorder by the grip handle; Add Row appends at the bottom; the trash icon deletes a row.
  • The table name edits in place in the top bar (auto-saves, "Saved ✓" indicator).
  • Edit Columns lets you rename, add, or remove columns — removing a column deletes its data from all rows (the dialog warns you).
  • The bar under the title shows the table's feed URL (/api/feed/<slug>) with a one-click Copy button.
PPT patterns
TIMEEVENT
9:30Sabbath School
11:00Divine Service
Table "Schedule", pattern schedule, value column EVENT
Today at our church: • {{schedule_1}} → Sabbath School • {{schedule_2}} → Divine Service
Placeholders in the template become row values, in row order
  • Open PPT Pattern in the table editor, enable the toggle, choose a pattern name and the value column.
  • Pattern names must be lowercase (a–z, digits, underscores, starting with a letter), unique across tables, and may not start with hymn (reserved).
  • When enabled, an ON badge shows on the button, and program item tags that would collide with the pattern (like schedule_1) are rejected.

10. vMix integration (API)

In vMix, add a Data Source of type JSON / URL pointing at any of these endpoints (use the machine's IP when vMix runs on another computer). vMix polls the URL and the mapped title fields update live.

EndpointContent
/api/hymns/service Every slide of every planned hymn, in order. Fields per row: HymnNumber, Title, Label, SlideText. An all-empty spacer row separates hymns (useful as a blank between songs).
/api/program/current The active program's items (muted excluded), each with title and subtitle. With no active program it returns a single row titled "No Active Program".
/api/program/{id}/json Same shape for a specific program (404 if it doesn't exist).
/api/feed/{slug} A data table's rows as JSON objects keyed by column name, in row order.
/api/version The app version, e.g. {"version": "1.1.1"}.

  {"HymnNumber": "123", "Title": "Amazing Grace", "Label": "Chorus",
   "SlideText": "Praise God, praise God…"},
  {"HymnNumber": "", "Title": "", "Label": "", "SlideText": ""}

11. Monitoring

  • The Monitoring page shows live requests-per-second charts for /api/hymns/service, /api/program/current, and each data table feed — a quick way to confirm vMix is actually polling.
  • Charts update every second over a rolling 60-second window; the badge next to each chart shows the current rate.
  • A flat zero line means vMix is not connected to that feed (check the Data Source URL and that both machines are on the same network).

12. Settings

  • Database File Path — where the SQLite database lives (all hymns, programs, tables, and settings). Changing it requires an app restart. If you point it at a path that doesn't exist yet, a fresh database is created there.
  • Templates Folder Path — where uploaded .pptx templates are stored. Changes apply immediately.
  • Both fields have a Browse button that opens a native file/folder picker on the server machine.
  • Sync tip: point both paths into a Google Drive (or similar) synced folder to share the same library and templates across several computers.
  • The Info card shows the app version, the database schema version, and the location of config.json — a small file next to the executable that remembers your custom paths between updates.
  • On a fresh install (or if the configured database is missing) the app routes you here first and unlocks the rest of the UI once paths are saved.
Startup & Updates
  • Start automatically when Windows starts — a switch that registers (or removes) the app in the current user's Windows startup entries. It is the same option the installer offers, so either place can turn it on or off. Available in the installed app only.
  • Application updates — the installed app checks the project's GitHub releases shortly after launch and once a day. When a newer version exists, a notification appears (once per browser session) and the Settings page shows an Install & Restart button with the release notes. Clicking it downloads the new installer, applies it silently, and relaunches the app — your data is untouched. Check for Updates runs a check on demand.

13. Tips & troubleshooting

SymptomLikely cause & fix
Generated PPT shows a different font than selected The font must be installed on the computer that opens the file — PowerPoint silently substitutes missing fonts. Stick to universal fonts or install the font on the presentation machine.
{{tag}} text still visible in the generated PPT The tag doesn't match any program item's PPT Tag (they must be identical), the item's Person/Description is empty, or the placeholder is split across separate text boxes. Keep each placeholder in one text box.
A hymn slide reads "(Hymn #N not scheduled)" The template asks for hymn N but the service plan has fewer hymns. Add hymns in the Hymns view or remove the extra {{hymn_N}} slide from the template.
vMix shows stale or no data Check the Monitoring page — if the feed's chart is flat, vMix isn't polling. Verify the Data Source URL, IP address, and firewall rules for port 10001.
An item is missing from the Dashboard / vMix feed It's probably muted — look for the green eye-slash icon in the program editor and click it to unmute.
Tag rejected as "reserved" or "conflicts with data table pattern" hymn_N style names and enabled pattern names are reserved for template placeholders. Pick a different tag name.
Changed the database path but nothing happened Database path changes take effect after restarting the application (the save message reminds you).
Long lyrics lines overflow on screen during the service Set the Wrap limit in the Hymn Editor to your safe line length — offending lines are highlighted red before they ever reach the screen.

Backups: everything except uploaded templates lives in the single SQLite database file — copying that file (plus the templates folder) is a complete backup.
